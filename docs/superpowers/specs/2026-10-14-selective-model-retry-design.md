# 失敗段換模型續跑與完成後開啟原檔

## 目的

使用者自行決定換模型，只重試勾選的失敗段；其他成功段保留。
辨識與翻譯是分開的階段，不可把文字模型直接當成轉錄模型。
全片成功寫出字幕後可一鍵用 Windows 預設程式開啟原始影片。

## 已確認的問題

- GUI 的 `_retry_selected()` 不重建 client，變更畫面選項不會影響重試。
- Gemini 辨識／翻譯模型目前是 translator 模組常數，翻譯沒有獨立選項。
- 進度身份包含模型；若直接改工作身份或重建進度，会失去原成功段的連續性。
- `_safe_err()` 為避免洩露 Key，省略一般錯誤文字；翻譯解析失敗只留下 RuntimeError。

## 工作與段落的分工

- 工作保留原始身份與 checkpoint 路徑，不隨重試模型改變；原檔案身份及
  split_plan 不變。來源語言、時間段位置不能在補跑中偷換。
- 以向後相容的可選欄位保存預設處理設定、各段／各階段的實際模型、
  安全錯誤分類及目前重試選擇。舊 schema 1 進度可讀，缺的欄位從舊身份推導。
- 每次使用者按重試，先驗證選項、Key 與階段支援，建立新的執行 client，
  只處理選中的失敗段。不要遷移、删除或覆寫其他獨立模型的工作。
- 成功段的 SRT 與保存的原文均不修改。全片匯出仍使用既有原時間座標。

## 快取及續跑

- 若原文已保存且驗證通過，只重跑翻譯；更換辨識模型不會無故重送該段音訊。
- 翻譯批次快取按翻譯模型隔離，不能把舊模型的部分譯文混入新模型結果。
- 辨識未完成時，新模型使用獨立原始回應／小段快取；舊失敗回應保留但不誤用。
- 未改模型的重試維持現在的快取規則；這項功能不聲稱修復無效時間戳，
  也不自動重送音訊或自動換模型。
- 中止後保存階段成果和實際設定；歷史清單還原工作後能繼續尚未成功的段落。

## 介面

- 辨識服務／模型和翻譯模型分開選擇。只列出已確認支援對應 API 與用途的模型，
  不捏造替代 Gemini 轉錄模型；若沒有同 API 的替代，可提示手動改用 Groq。
- 失敗區顯示段號、階段、模型、安全原因，以及是否可透過換模型重試。
- 成功段不進入失敗勾選清單。工作進行中禁止切換執行設定或發起第二次重試。
- HTTP 429/額度不足提示等待或由使用者選擇其他適用模型，不承諾不同模型獨立額度。
- 驗證失敗保留進度；內容封鎖顯示原因，不提供用換模型繞過的操作建議。
- 全部段落成功且字幕寫出後才顯示「開啟原始影片」；點擊時開啟本次成功
  工作的原檔，不是後來輸入欄位所選的其他影片。不自動播放。
- 新工作開始時清除上次完成按鈕；檔案被移除或 Windows 開啟失敗時顯示安全錯誤。

## 安全原因分類

保留階段、HTTP code、服務狀態／finish reason、時間戳 reason 等可控資訊。
分類至少包含：額度不足、認證／權限、服務不可用／逾時、不支援模型、
內容封鎖、輸出截斷、JSON／字幕對應格式異常、時間軸驗證失敗、未知錯誤。
未知錯誤不猜原因；不顯示完整 URL、API Key、音訊／字幕內容或原始 response。

## 驗收

1. 兩段工作，第一段失敗、第二段成功；換模型只處理第一段，第二段保持原樣。
2. 翻譯失敗换翻譯模型不重新辨識；不能重用另一模型的翻譯批次。
3. 辨識失敗換辨識服務／模型不讀另一模型的原始回應。
4. 保存／重開後仍沿用同一分段計畫，模型來源資訊不遺失；舊 JSON 可續跑。
5. 各錯誤分類有回歸測試，且不能洩露模擬 Key 或 URL。
6. 只有全成功才可開原檔；部分成功、全失敗、停止及開啟例外均有測試。
7. 暫存清理及既有全套測試保持通過，文件更新。測試不使用使用者 API 額度。

## 不在範圍

自動備援、自動換模型、繞過内容封鎖、整批影片排隊、強制重新辨識成功段、
自動播放、這次直接處理使用者影片或修復 Groq 異常時間戳。
